# 2026-11-07：连着回两遍、表情包当文字发

## 一、一次连发，回了两遍

聊天记录（20:03）：

```
20:03:30 你：在啊
20:03:31 你：怎么了
20:03:34 你：肥鱼
20:03:39 她：你才是肥鱼 / 大晚上的叫我这个 / 干嘛 有事说事
20:03:40 她：？ / 你谁啊 / 找我啥事
```

两段回复差 1 秒，第二段还答"你谁啊"——她其实刚说完话。

原因两个，都在海螺这边：

1. **合流窗口只看最后一条**。`Merger` 每来一条就把 1.5s 计时器重置，
   所以 30、31 合成一批在 32.5s 就开跑了；34 再进来只能另起一批。
   两批各自调模型，回复就叠在一起。
2. **每轮不带历史**。`run_turn` 只发 system + 这一批消息，模型不知道
   自己 5 秒前说过什么，所以第二批回得像陌生人。

改法：

- **保持原来的尾随窗口**：只在最后一条之后等 `merge_window_ms`，
  **总时长不设上限**——她一直补就一直等，最后一条发完 1.5 秒才开跑。
  （`merge_max_wait_ms` 默认 0 = 不限；真要限再填。）
- 同一个会话一把锁（`turn_lock`）：同一时间只跑一轮，后面排着。
- `recent_turns/remember_turn`：每个会话留最近几句（≤1800 字）拼进 messages，
  她下一轮知道自己刚说过什么。
- 顺带按 `message_id` 去重：协议端重连推同一条不会再回一遍。

所以你那晚的 30/31/34 序列，现在是这样：34 秒那条到了之后计时到 35.5，
一批三条一起开跑，只回一次。

配置：`merge_window_ms`（窗口，默认 1500）、`merge_max_wait_ms`（默认 0 不限）。

## 二、表情包发送异常

现象：她回「【表情包：猫猫-眯眼凝视】」，QQ 里看到的是这串方括号文字。

原因：

1. 模型被教成"要发表情就写【表情包：名字】"，但**没有任何东西把这行换成图**，
   `send_lines` 直接当普通文本发出去了。
2. 就算想换也没得换：`fetch_custom_face` 拉 QQ 收藏表情返回 0 张
   （count=10/50、url/id 两种都试过，都是空），库里 `stickers` 表也是 0 行。

改法：

- `send_lines` 认这一行：`【表情包：名字】` / `【表情：名字】` 单独一行 →
  调 `stickers.pick_and_send()` 真发图；名字对不上、手里没有、服务没接上 →
  **整行丢掉**，绝不把方括号发出去；行内出现的标记也会被清掉。
- 提示词（`core/stickers.on_prompt`）：格式写清楚"单独一行、从列表里挑、
  别自己编"；手里 0 张时直接告诉她"别写【表情包：…】"。
- `main.py` 把 `Stickers` 放进 `ctx.services["stickers"]`，插件才够得着。
