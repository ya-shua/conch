# QQ 看视频：存下来，等被要求时再看（2026-11-10）

> 讨论定稿，**尚未实现**。本文只记设计。

## 一、这是哪条路

她有两件跟"看视频"有关的事，**互相独立，别混**：

| | 刷视频（snow-video-kit） | 本文：QQ 看视频 |
|---|---|---|
| 是什么 | 她的**娱乐**，值班刷 B 站/抖音 | 聊天里别人发的视频 |
| 谁决定看 | 她自己挑（程序采集 → 她挑 → 她看） | **别人明确要求**才看 |
| 触发 | 值班场景常挂 `watch`/`push` | 话里出现"你看看这个/视频里说了啥"才挂 |

## 二、规则

| 场景 | 看不看 | 为什么 |
|---|---|---|
| 聊天里有人发视频/动图 | **不自动看**，只存下来 | 每看一条都要过视觉模型，白花钱 |
| 有人说"你看看这个 / 视频里说了啥 / 这段是不是…" | **才看**（这一轮才把看视频的工具挂上） | 明确要求 |
| 有人发**图** | 仍自动看 | 一张图一次调用，一天限 100 次够用；不看就成了"看不见的东西" |
| 有人发**语音** | 仍自动听（ASR 转写） | 同上，且早就配好了 |

一句话：**图和语音是常态，自动；视频是重活，按需。**

## 三、为什么要"存而不看"

只下载、不分析，几乎不花钱（只占磁盘）。但如果进站时不下载，QQ 的视频链接过一会儿就失效——
等她被要求看的时候，**已经没有东西可看了**。

所以三步：

1. **进站就下载**到本地缓存（`data/media/`）
2. **不碰模型**：不抽帧、不调视觉、不产生费用
3. **被要求看时**，拿这份本地文件去抽帧 + 听音轨

## 四、存什么（两种，分开管）

| 存什么 | 存哪 | 留多久 | 用途 |
|---|---|---|---|
| **视频文件** | `data/media/最近视频/` | 只留最近 N 条 / 3 天（待定，见下） | 纯缓存：换时间点再看、重看 |
| **解析结果**（帧描述、音轨转写） | SQLite（按文件指纹记一行） | **永久** | 已经花过钱，同一条不能重复收费 |

关键：**用文件指纹（sha1）当 key**。

- 第二次有人说"再看看这个" → 算哈希 → 命中就直接返回上次的描述：**零成本、零等待**
- 视频文件过期删了也没关系，解析还在，她照样能说"我上次看过这条，里面是……"
- 换个时间点看（"第 2 分钟那段"）→ 只重算那一段，其余复用

原则：**素材可以扔，得出的结论不能扔。**

## 五、现状（为什么现在看不到）

海螺入站只挑 `image` 段：

```python
# plugins/conch/main.py  image_urls()
if getattr(seg, "type", "") != "image":
    continue
```

`video` / 动图（`mface`）段**直接忽略**——她根本不知道有这回事。所以要让她"能看 QQ 视频"，
得先做第四节那个"进站就下载"。

## 六、待定的两个数字

1. **视频文件保留几条 / 几天**
   - 太少：想看时已经被覆盖
   - 太多：占磁盘
   - 倾向：**10 条 或 3 天，谁先到算谁**
2. **单个文件上限**
   - 倾向：**50MB**，超过就只记"有个视频但太大，没存"

解析结果不用定：永久留，按指纹去重。

## 七、成本与限制（留影现有配置）

- 视觉：`glm-4v-flash`（智谱），日限 **100 次**，每条消息最多 3 张
- 一条视频抽 3 帧 ≈ **¥0.003**
- 日限吃满 ≈ 一天能看 33 条视频；超了要如实降级成"没看到画面"，不能编
- 抽帧用留影自带 `bin/ffmpeg.exe`
