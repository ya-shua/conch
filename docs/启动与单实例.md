# 启动、重启与「只能有一套」

## 一个入口

桌面上的「海螺」只做一件事：把 `scripts/tray.py` 拉起来（`start_conch.vbs` → pythonw，无窗口）。

托盘负责：

- 把全套服务拉起来（海螺本体、SnowLuma、记忆库、情绪面板、微光域、声来……）
- 本体要是崩了/被关了，自动拉回来（图标在 = 服务在）
- 面板窗口只在**你点它**的时候打开（双击图标 / 菜单「打开面板」）
- 菜单「退出（全部停止）」才真的全停

## 重启不弹窗

以前「重启」走的是 `start_conch.vbs` → 新托盘 → 发现服务不在 → 顺手 `open_panel()`，
于是每次重启都自己弹一张面板出来；`restart_conch.py` 里那句 `powershell` 也没加隐藏标志，
还会闪一下黑窗口。

现在：

| 动作 | 行为 |
| --- | --- |
| 代码热重启（`restart_conch.py`） | 只杀本体 → 直接拉 `start_all.py`；**不开面板**、powershell 带 `CREATE_NO_WINDOW` |
| 托盘菜单「重启海螺」 | 全停 → 重启；**不开面板** |
| 双击桌面图标 / 托盘双击 | 这是用户主动要看面板：服务在就只把窗口提到最前，服务不在就先拉起来再开 |
| 首次启动（服务本来是停的） | 开一次面板 |

## 三重锁：同一套只能有一个真身

| 锁 | 位置 | 抢不到会怎样 |
| --- | --- | --- |
| 托盘 | `data/tray.lock` | 只把面板打开就退出（不会再起一套服务） |
| 本体 | `data/host.lock` | 直接退出并写一条 warning（两个本体会互相踢 QQ 线） |
| 窗口守卫 | `data/guard.lock` | 直接退出（守卫每 2 秒扫一遍全部窗口，多几个纯属烧 CPU） |

三把锁都是 `O_CREAT | O_EXCL` 原子占位，不是「先读再写」—— 后者有空窗，
双击两下就能起两个托盘。锁里记 pid，进程没了就算失效，下次自动接管。

## 任务管理器里看到「同名两行」是正常的

`.venv\Scripts\pythonw.exe` 是个**壳**：它自己不干活，会把
`C:\Users\...\pythoncore-3.14-64\pythonw.exe` 拉起来跑同一份脚本。
所以一个逻辑进程会显示父子两行（父进程是壳），不是起了两个实例。
判断是不是重复，看 `data/*.lock` 里的 pid，别看任务管理器的行数。

## 窗口守卫（window_guard.py）

服务自己还会再起子进程（SnowLuma 的 worker、微光域拉的 Chrome、tide 的重载子进程…），
这些孙进程可能带着控制台窗口冒出来。守卫每 2 秒扫一遍顶层窗口，
只把「属于我们这套服务路径的白名单内」的控制台窗口 `ShowWindow(SW_HIDE)`，
不碰用户自己开的窗口。日志在 `data/logs/window_guard.log`。
