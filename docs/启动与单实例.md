# 启动、重启与「只能有一套」

## 一个入口

桌面上的「海螺」只做一件事：把 `scripts/tray.py` 拉起来（`start_conch.vbs` → pythonw，无窗口）。

托盘负责：

- 把全套服务拉起来（海螺本体、SnowLuma、记忆库、情绪面板、微光域、声来……）
- 本体要是崩了/被关了，自动拉回来（图标在 = 服务在）
- 面板窗口只在**你点它**的时候打开（双击图标 / 菜单「打开面板」）
- 菜单「退出（全部停止）」才真的全停

## 重启不弹窗

以前「重启」走的是 `start_conch.vbs` → 新托盘 → 发现服务不在 → 顺手 `open_panel()`，
于是每次重启都自己弹一张面板出来；`restart_conch.py` 里那句 `powershell` 也没加隐藏标志，
还会闪一下黑窗口。

现在：

| 动作 | 行为 |
| --- | --- |
| 代码热重启（`restart_conch.py`） | 只杀本体 → 直接拉 `start_all.py`；**不开面板**、powershell 带 `CREATE_NO_WINDOW` |
| 托盘菜单「重启海螺」 | 全停 → 重启；**不开面板** |
| 双击桌面图标 / 托盘双击 | 这是用户主动要看面板：服务在就只把窗口提到最前，服务不在就先拉起来再开 |
| 首次启动（服务本来是停的） | 开一次面板 |

## 三重锁：同一套只能有一个真身

| 锁 | 位置 | 抢不到会怎样 |
| --- | --- | --- |
| 托盘 | `data/tray.lock` | 只把面板打开就退出（不会再起一套服务） |
| 本体 | `data/host.lock` | 直接退出并写一条 warning（两个本体会互相踢 QQ 线） |
| 窗口守卫 | `data/guard.lock` | 直接退出（守卫每 2 秒扫一遍全部窗口，多几个纯属烧 CPU） |

三把锁都是 `O_CREAT | O_EXCL` 原子占位，不是「先读再写」—— 后者有空窗，
双击两下就能起两个托盘。锁里记 pid，进程没了就算失效，下次自动接管。

## 任务管理器里看到「同名两行」是正常的

`.venv\Scripts\pythonw.exe` 是个**壳**：它自己不干活，会把
`C:\Users\...\pythoncore-3.14-64\pythonw.exe` 拉起来跑同一份脚本。  <!-- privacy-ok -->
所以一个逻辑进程会显示父子两行（父进程是壳），不是起了两个实例。
判断是不是重复，看 `data/*.lock` 里的 pid，别看任务管理器的行数。

## 窗口守卫（window_guard.py）

服务自己还会再起子进程（SnowLuma 的 worker、微光域拉的 Chrome、tide 的重载子进程…），
这些孙进程可能带着控制台窗口冒出来。守卫每 2 秒扫一遍顶层窗口，
只把「属于我们这套服务路径的白名单内」的控制台窗口 `ShowWindow(SW_HIDE)`，
不碰用户自己开的窗口。日志在 `data/logs/window_guard.log`。

## 面板窗口怎么认（别按标题认）

控制台是浏览器里的一个页面，所以「打开面板」本质是**找到自己那个窗口、把它提到最前**。
这里踩过一个坑：早期是按窗口标题认的（`海螺|运行总览|模型接入|发言策略|插件`），
结果 GitHub 上 `ya-shua/conch` 的仓库页标题里也有「海螺」——
点启动时被当成面板提上来，真正的控制台反而不开，表现就是
**「点启动打开的是 GitHub」** 和 **「明明没有面板却说已经开着，怎么也打不开」**。

现在只认两样东西：

1. **窗口句柄**（`data/panel.hwnd`）—— 还活着就直接提上来，最快；
2. **进程号**（`data/panel.pid`）—— 句柄失效时按 PID 找它自己的窗口，
   并且核对这个 PID 的 exe 确实是浏览器。

**面板用独立的浏览器配置目录**（`data/panel-profile`），不和你平时开的浏览器共用一个实例。
否则 Chromium 会把 `--new-window` 交给已经在跑的那个实例，窗口可能被并进后台/隐藏的窗口里，
看起来就是「打不开」。

标题只用来确认「这个窗口有没有内容」，不再参与认领。

## 一键启动读的是哪份清单

两个文件，分工不同，别混：

| 文件 | 是什么 | 谁写 |
|---|---|---|
| `launchers.json` | **启动清单**：id / 名字 / 想不想显示、密码这类本机设定 | 面板里改（本地，不入库） |
| `config.json` | **宿主配置**：`look.node` 在哪、`plugin_paths` 指向哪些插件目录 | 安装 / 设置页 |

清单里通常只写 `id` 和名字，`cwd` / `cmd` / `port` / `url` 由各插件的
`metadata.json` 里的 `launch` 段补（`runtime` + `entry` 那种写法还要用到
`config.json` 里的 `look.node`）。

所以 `launchers.load()` 必须拿到 **config.json**；以前 `scripts/start_all.py`
传的是 `launchers.json`，`_host_config()` 读到的是一个 list，
`cfg.get("look")` 直接抛异常 —— 兜底后只剩「裸清单」，
`cwd`/`cmd` 空着，一键启动就只会记 `路径不对：`，环形的心 / 娱乐 / 微光域 / 留影 全起不来。

现在 `_host_config()` 两种文件都认（给 launchers.json 时找同目录的 config.json），
`start_all.py` 也改回传 `CONFIG`；`load()` 里就算某个插件的 metadata 写坏了，
也只少那一条，不会整份清单都读不出来。
