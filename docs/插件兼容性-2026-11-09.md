## 当场事故：20 分钟里她连发了三条（已修）

打开宿主桥之后，23:24:33、23:28:20、23:29:20 她发了三条（中间还有一次发送失败重来）。
查完是两个原因叠在一起：

1. **一次开口记了两遍**。宿主回执 `report_proactive(sent=true)` 记一次叫醒，
   mood 插件的 `speech.gate`（她真的说出去了）又记一次 —— 两边都调 `mark_woke`。
   于是「今天叫醒几次」翻倍，递减冷却 90 → 70 → 50 … 一路掉到 5 分钟下限：
   **越聊越黏**，看起来像冷却没生效。
2. **两个 Tide 同时在推进时间**。Windows 默认允许两个进程绑同一个端口
   （`allow_reuse_address`），重启/更新时新旧两个都在跑：各有一份内存里的
   `last_wake_at`，共用一份 `state.json`，于是 A 刚记住「说过了」，
   B 还以为「没说过」，交错发。

修法（汐 v1.4.1）：

- `mark_woke()` 30 秒内的重复合并成一笔 —— 不管谁先谁后，一次开口只算一次；
- 面板 `allow_reuse_address = False` + `data/panel.lock` 单例锁，第二个实例启动即退出，
  并打印「已经有一个面板在跑了」；
- 新增 `tests/test_single_instance.py`（7 条）：重复计时、冷却真的挡住第二次、
  锁文件认活进程/认死进程、`_Server` 不复用端口。

修完实测：汐 197 个测试全过；第二个实例起不来；`should_wake` 在冷却期返回
`false`（理由「还在冷却（还要 N 分钟）」）。

## 体检发现的真问题（按要紧程度）

1. **有的插件 metadata.json 从来没进过 git**：留影、汐。别人 clone 或下 release 包拿不到身份文件，宿主认不出来 —— 而且一键更新走的是 tarball，也永远补不上。**要你点头才能 add + 发版。**
2. **版本号多处漂移**：声来 `.zcode-plugin/plugin.json` 还是 1.8.1（代码和 metadata 是 1.9.0）；刷视频插件的 MCP `serverInfo` 以前报 0.3.0 / 0.1.0（已修）。宿主按版本判断「要不要更新」时会误判。
3. **MCP 入口不机器可读**：以前只能翻代码或 `plugin.json` 找 `mcp/server.py`。契约里已加可选 `mcp` 字段（entry/runtime/tools），声来、微光域已填真实工具名。
4. **拿走后跑不起来的硬编码**：刷视频插件里 `SCROLL_CONSOLE`、`douyin.toolsDir`、`conch.homeDir`、`media.liuyingHome` 全是本机绝对路径，换台机器必改。表情包库要自己装 aiohttp；留影/声来都要模型 key 才有核心能力。
5. **「假活」**：刷视频插件端口被占时只记日志、进程不退，只能靠 `/api/health` 连不通发现。声来启动保护写死 17878/17879，传别的端口也不让起。  <!-- privacy-ok -->
6. **测试脚本会花钱**：声来根目录 `test_speak_api.py` 顶层直接发请求，在仓库根跑 `unittest discover` 会真的合成语音。
7. **免 token 的探活端点会漏密码**（抓到一个真的）：环形的心原来那个 `/api/health` 是一份诊断大对象，里面带
   `server.token`、`onebot.token`、`consolePassword`（QQ 控制台密码）明文。它以前要鉴权所以没事，
   改成免 token 后等于**本机任何一个网页都能 fetch 到密码**。已要求改成「免 token 只给最小字段、带令牌才给富信息」，
   并在 `compat_check.py` 里加了泄露检测列（响应体出现 `password` / `token` / `sk-` 这类字样就直接标 ❌）。
