# 插件对接契约（每个插件都要有这四样）

> 目标不是「我的插件能跑」，而是**别人只拿走这一个文件夹，也知道怎么接、接得对不对、能用上几分能力**。
> 规则只有一句：**身份走 metadata，能力走 /api/manifest，活没活走 /api/health，剩下的写进 docs/对接.md。**

## 一、四件套

| 编号 | 东西 | 谁读 | 缺了会怎样 |
|---|---|---|---|
| 1 | `metadata.json`（仓库根） | 海螺 loader / 任何人 | 宿主不知道它是什么、怎么启动、面板在哪 |
| 2 | `GET /api/health` | 宿主、探活脚本、面板前端 | 只能靠试端口猜它活没活 |
| 3 | `GET /api/manifest` | 宿主、外部集成方、你自己debug | 别人只能翻代码猜它有什么能力 |
| 4 | `docs/对接.md` | 人 | 拿到手不知道从哪接起 |

四个都不需要联网、不需要 token、不含隐私。

## 二、metadata.json 的必填字段

```jsonc
{
  "id": "eyes",                  // 全局唯一，短，小写
  "name": "留影",
  "version": "1.8.0",            // 必须和代码里的版本常量一致（检查脚本会对）
  "kind": "app",                 // app | tool | extension
  "description": "一句话它是什么",
  "page": "http://127.0.0.1:5188/",
  "port": 5188,
  "launch": {                    // 宿主拿它来一键启动
    "runtime": "node",           // node | python | exe
    "entry": "src/panel.mjs",
    "args": ["--port", "5188"],
    "port": 5188,
    "url": "http://127.0.0.1:5188/"
  },
  "capabilities": ["看图描述", "视频抽帧", "文字转写"],   // 3~6 条，中文短语，按真实能力写
  "standalone": {                // 别人单独拿走时看这段
    "works_alone": true,
    "needs": ["一个支持视觉的模型 key"],   // 缺什么就跑不起来，一条一句
    "how": "填好 key 后 node src/panel.mjs --port 5188，浏览器打开 5188"
  },
  "contract": "docs/对接.md"
}
```

`capabilities` 写的是**能力**（能干什么），不是**接口**（哪个 URL）；接口在 manifest 里。

### 可选：`mcp`（有 MCP 工具就填）

```jsonc
"mcp": {
  "entry": "mcp/server.py",          // 相对仓库根
  "runtime": "python",               // python | node
  "args": [],
  "tools": ["voice_tts", "voice_clone"]   // 真实工具名，别写「若干工具」
}
```

没有这个字段，宿主/别的 AI 只能去翻适配层代码找入口 —— 这是「接得上但接不全」的典型。
填了它，`POST /api/manifest` 的 `capabilities` 里也要能对上这些工具名。

## 三、`GET /api/health`

```json
{ "ok": true, "id": "eyes", "version": "1.8.0", "uptime_s": 42.7 }
```

- 进程活着、能服务 → `ok: true`。**不检查外部依赖**（模型 key、数据库）——那些属于「能力降级」，写在 manifest 里。
- 2 秒内必须回；回不了就等于挂了。
- 已经被旧代码用着的（比如环形的心面板前端在轮询它）**只能加字段，不能删字段**。

## 四、`GET /api/manifest`

```json
{
  "ok": true,
  "metadata": { /* 仓库根 metadata.json 原样 */ },
  "runtime": { "port": 5188, "pid": 1234, "started_at": "2026-11-09T23:20:00+08:00" },
  "capabilities": [
    { "name": "看图描述", "kind": "http", "how": "POST /api/describe {\"image\": \"<路径或URL>\"}" }
  ]
}
```

- `kind`：`http` / `mcp` / `file` / `event`，指别人**怎么调**。
- 有 MCP 工具的插件，把工具名列进 `capabilities`（名字要和实际注册的一致）。
- 不许出现：key、绝对路径里的用户名、聊天内容、用户数据清单。

## 五、失败语义（必须写清楚，别让调用方猜）

每个插件在 `docs/对接.md` 里回答这四问：

1. 没配置（没 key / 没登录 / 库是空的）时返回什么？
2. 超时 / 忙 / 正在被占用时返回什么？
3. 调用方该重试还是该放弃？
4. **哪些操作是不可逆的**（写库、发消息、删文件）——这类必须能回「我没做成」。

最后一条是这个生态里踩过的坑：**「发出去了」和「我以为发出去了」是两件事**。凡是替别人做动作的（发消息、写记忆、调外部服务），返回值里必须带 `sent` / `ok` 这种**真实结果**，失败了要如实回 `false` + 原因，不许「静默成功」。

## 六、海螺这边怎么消费

| 场景 | 走哪条 |
|---|---|
| 一键启动 / 面板卡片 | `metadata.json` 的 `launch`（`scripts/start_all.py` 合并 `launchers.json`） |
| 当工具用 | 插件自己起 MCP 服务，海螺 `plugins/*/metadata.json` 里的 `mcp` 段 |
| 让插件主动说话 | `POST {host}/api/proactive/say` + 回报 `report_url`（见汐的 `docs/主动消息-对接.md`） |
| 检查「接得对不对」 | `python scripts/compat_check.py`（下表就是它的输出格式） |

## 七、检查脚本

```powershell
cd D:\我的电脑\桌面\插件\海螺
.\.venv\Scripts\python.exe scripts\compat_check.py          # 只看契约（不需要服务在跑）
.\.venv\Scripts\python.exe scripts\compat_check.py --live   # 连上正在跑的服务，验 health/manifest
```

输出每行一个插件：`metadata` / `docs` / `standalone` / `health` / `manifest` / `version` 六列，
✅ 合规、❌ 必须修、`·` 没在跑（跳过）。有 ❌ 时退出码 1。

## 八、三种接法（给写文档的人）

- **HTTP 面板**（人也用、脚本也用）：所有交互都过 `/api/*`，前端只是其中一个客户端。
- **MCP 工具**（宿主调）：工具名、参数、返回都在 `docs/对接.md` 里列全，别只说「有工具」。
- **事件 / 文件**（进程之间不直接说话时）：约定文件路径 + JSON 格式 + 谁写谁读。

只要这三条里有一条能自洽跑通，这个插件就算能「单独拿出去用」。
