# 称呼卡、身份与上下文

这篇讲「她眼里谁是誰」「记住的东西长什么样」「刚才聊过的话从哪来」。
人设卡（角色性格）在 `roles/`，这里只讲数据和提示词这一侧。

---

## 1. 她看到的一行长什么样

```
[群123456] 阿星(小鱼) #123456789: 在吗
[群123456] 群主 老墨 #111222333: 在吗
[群123456] 管理员A #1234567890: 在吗
[私聊] 管理员 #1234567890: 肥鱼
```

| 位置 | 含义 |
| --- | --- |
| `[群…]` / `[私聊]` | 这条话是在哪儿说的 |
| 冒号前 | 说话人的标签 |
| `#` 后面 | QQ 号（昵称会改，号码不会） |

标签只有四种来源：

1. **称呼卡上的人** → 卡名（`管理员A`）；只有一张卡且叫「管理员」时，群里显示 `管理员`、私聊显示 `管理员 #号`
2. **群主 / 群管** → `群主 名字 #号`、`群管 名字 #号`：这是他在**这个群**的职务，
   不是「自己人」，没有管理员权限
3. **别人把昵称改成「管理员 / 管理员本人 / 群主」** → `冒充管理员 #号`
4. **普通群友** → `名字 #号`

她自己发的话在历史里不加前缀（`role=assistant`），跟用户的区别靠角色分，不靠文字。

## 2. 称呼卡（面板「白名单 → 称呼卡」）

一张卡 = 一个自己人，可以挂多个 QQ 号（同一人的几个号）；多张卡 = 多个人。

```json
{
  "owner_qq": "1234567890",
  "admins": [
    {
      "name": "管理员A",
      "ids": ["1234567890", "9876543210"],
      "call": {
        "private": "老爹",
        "group": "老大",
        "by_group": { "123456": "老翰" }
      }
    },
    { "name": "管理员B", "ids": ["12345678901"] }
  ]
}
```

- `owner_qq` 是兼容字段：没写 `admins` 时，它自动变成一张叫「管理员」的卡
- 卡上的号都算**管理员**：私聊放行、可以远程指挥她往群里发话（白名单 `allow.private` 另算）
- 几个号写进记忆库是**同一个人**（见第 4 节）

### 叫法怎么定

| 字段 | 什么时候用 |
| --- | --- |
| `call.by_group[群号]` | 在这个群里优先用它 |
| `call.group` | 群里没单独设置时用 |
| `call.private` | 私聊用 |

优先级：**本群单独设置 > 群里默认 > 私聊**。都没填就什么都不加。

提示词里只有一行，只在当前场景注入：

```
【叫法】管理员A 希望你叫他「老爹」。
```

约 10 token；填的人越多也不会变长，因为只带**当前这个人**那一句。

**词本身不在这里**——爸、管理员、老爹、提款机、老头这些是性格的一部分（人设里那套），
称呼卡只决定「此情此景她想用哪个」，不做词库。

## 3. 记忆库里的身份

每听到一句（群/私聊都算），按这个格式入库：

```
source  : group / private
speaker : 卡名（自己人）｜名字 #号（别人）
content : [群123456] 管理员A #1234567890：在吗
```

- `speaker` 用**卡名**：一张卡两个号 → 同一行 `speaker` → 她回忆「关于这个人的事」时不会只捞到一半
- 号码只留在 `content` 里，要追溯「是哪个号说的」再看
- 群主/群管只是职务，不参与身份判定

```python
    # 群聊：只取这个群
```

规则：

| 项 | 值 |
| --- | --- |
| 条数上限 | 20 条 |
| 字数上限 | 1800 字 |
| 往回看 | 24 小时（隔了一夜但不到一天，她接得上） |
| 排序 | 按 `ts`（同一毫秒再按写入顺序） |
| 去重 | 按 `message_id` |
| 当前这一批 | 已经从库里读出来了，但要跳过（马上作为新消息发，别重复） |

所以：A 号说一句、B 号接一句、A 号再说一句，她看到的就是这个真实顺序。
群里的上下文不会串到私聊，反过来也一样。

## 5. 面板上在哪

- 「白名单」页：管理员 QQ（兼容用法）、**称呼卡**、群白名单、私聊白名单、全部放行
- 保存走 `PUT /api/settings`，`admins` 和 `allow` 一起提交；同一个号挂到两张卡上会被拒（400）

## 6. 相关的坑

- **昵称会变**：所有身份判定都走 QQ 号，昵称只当显示用
- **一个群好几个人都叫「管理员」**：真实昵称撞上了就按「冒充」标，靠号码区分
- **改卡名**：卡名是身份键（记忆库 `speaker`、上下文合并），改名等于换了个人设标签，
  老记录还留在旧名字下
- **人称**：只有卡上的人是「自己人」，群职务不是
