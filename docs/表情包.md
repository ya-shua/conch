# 表情包：她自己的收藏

以前是「见到就收」，收到的东西她也不认识 —— 提示词里只有 `[动画表情]` 四个字，
她挑的时候其实是瞎挑。现在改成三步：

## 1. 先看懂（视觉模型）

群里冒出表情 → 存下来 → 交视觉模型看一眼。这里用的提示词**跟聊天看图不是同一套**：
聊天看图问的是「图里有什么」，表情包问的是「这表情什么意思、什么场合适用」。

拿到两样：

- 一句意思：`一个穿着白色制服和蓝色头发的卡通女孩`
- 3–5 个**情绪/场合标签**：`可爱、卖萌、撒娇`（不是「图里有帽子」那种描述）

标签就是她挑表情的把手：`【表情包：撒娇】` 就对得上。
提示词里给她的格式是「名字（意思；标签）」。

用的是「留影」那套视觉配置（现在是智谱 `glm-4v-flash`）。

### 为什么动图要抽第一帧

智谱这档视觉接口吃的是**单张静态图**（jpg / png / webp），GIF 动图是很多帧打包在一起，
当图片塞进去会直接 `400 图片输入格式/解析错误` —— 跟大小没关系，是格式不吃。
所以动图先让 `ffmpeg` 抽第一帧成 PNG 再给模型（用的是留影自带的 `bin/ffmpeg.exe`，抽好的帧缓存在 `data/stickers/_frames/`）。

### 意思只存在表情包库，不进记忆库

收下的表情，视觉模型看懂之后把**意思和标签写进表情包库**（`stickers.meaning` / `tags`），
就这样，一条不多：

> 意思：一只猫四脚朝天躺着摆烂｜标签：摆烂、累

- 提示词里列的「手里有 N 张表情，常用的这几张：…（带意思）」读的就是这里；
  她发图时按意思/标签找图，也读这里 —— **只有一份，改一次全对**；
- 她给过的说法（`keep_sticker` 时说的、或面板起的名）存在 `remark`，跟着那张图走，
  提示词里也带着；她聊天时怎么讲由她自己发挥，不写死台词；
- **不进记忆库**。以前没有视觉模型，意思没地方存，只能借记忆库记一句
  （`conv_key=self:stickers`）；现在视觉模型直接写进库，那份就是冗余副本：
  在面板改了图的意思，记忆里那条不会跟着变，错的一直留着，还会被检索出来当真。
  表情只归海螺，记忆库只装**她自己经历的事**。
- 因此也没有「表情要不要遗忘」这回事：图还在，意思就在；图删了，意思一起没。
  真有什么事她想记住（“今天他发这张把我逗笑了”），那是她自己用 `ring_remember` 记，按圈和遗忘规则走。
- 删掉一张：库里的行和文件一起删，不再补「已删除」的记忆。

## 2. 她想要才收

| 收法 | 行为 |
| --- | --- |
| `want`（默认） | 先放**缓存区**，提示词里单独一段「群里新看到这几张还没收」；她觉得好玩就调 `keep_sticker` 收下 |
| `auto` | 看到就直接算她的 |
| `off` | 完全不收 |

缓存里放太久（默认 7 天）她一直没要，就自动清掉，文件一起删。
计时从**最后一次见到**算：同一张又被刷到，`last_seen` 刷新、排到缓存区最上面，7 天重新开始数。

`keep_sticker` 是给她自己用的工具：说个名字或标签就行（先认标签正好对上的）。
**找不到就不收**：她说「收那只猫」但缓存里没有猫，回「缓存区里没找到」，
不会拿最新那张糊弄她。面板上缓存区也有「收下」按钮，主人可以直接替她收。

提示词里只列**看得懂**的候选（有描述/标签的）：一排「动画表情」她没法挑，
一张都没看懂时这段就不写。

## 2.5 两个区（别混）

| 区 | 放什么 | 目的 | 上限 |
| --- | --- | --- | --- |
| **缓存区** `data/stickers/_cache/` | 还没被她收下的图（`source=candidate`） | 同一张图再出现时**不用重新下载、不用重新理解** | 张数（默认 100 / 硬上限 200）+ 体积（默认 200MB），满了淘汰最久没出现的 |
| **缓冲区** `sticker_vision.status='fail'` | 视觉模型没调通的那几张 | 模型恢复后**自己接着认**，不白丢 | 张数（默认 200），按 1 / 5 / 20 分钟退避，一张最多试 3 次 |

两件事要分清：**缓存区管图**，**缓冲区管「还没看懂」这件事**。一张图可以同时在两边
（图在缓存区等着，账在缓冲区排队）。

收下时是**移动**文件（`_cache/xxx.gif` → `xxx.gif`），不复制，库里的路径跟着改。

## 2.6 各种上限（都在表情包页，改完立即生效）

| 设置 | 默认 | 管什么 |
| --- | --- | --- |
| 每天最多看几张 | 30 | 只算**看成功**的，失败不占额度 |
| 一张最多试几次 | 3 | 试满标「没看懂」，面板可以手填标签 |
| 缓冲区最多排几张 | 200 | 排队等重试的图，超了丢最旧的 |
| 缓存区最多存几张 | 100 | 还没收的图 |
| 缓存区上限（张 / MB） | 200 / 200 | 硬上限，谁先到谁淘汰 |
| 理解记录留几天 | 90 | 没收录的「看过没」记账；已收下的永久留 |
| 每张给几个标签 | 2 | 提示词里每张表情带几个标签（省 token） |
| 提示词里列几张候选 | 3 | 0 = 不告诉她有新表情 |
| 每分钟 / 每小时最多收 | 2 / 10 | 防刷屏 |

聊天里看图的每日上限在 `look.max_images_per_day`（默认 200），和表情包分开算：
计数落在海螺自己的 `counters` 表（按天），面板上也能改（表情包设置 →「聊天看图」那一段）。

## 3. 发的时候按意思挑

`【表情包：无语】` 这种按意思对得上就行：

1. 先认**标签正好等于**它的那张（`tags = 无语`）；
2. 再认备注正好等于它的；
3. 都没有才看包含关系（备注 / 意思 / 标签 / 摘要里含这个词）；
4. 还找不到就随机一张。

做成这样是因为标签是顿号拼的一串（`摆烂、无语`），纯包含会挑错。
缓存区里的图不算她的，发不出去。

## 三道闸：防重复调模型

1. **记账**：`sticker_vision` 表按 sha1 记「这张看过没」，看过就直接用缓存，
   同一张图永远只调一次模型（入库前还会按 sha1 去重，同一张不会收两遍）；
2. **在跑的不重入**：同一张正在看的时候，再来一次直接跳过；
3. **失败进缓冲区**：没看成（网络 / 模型报错）记一次失败 + 下次时间，
   按 1 / 5 / 20 分钟退避重试，最多 3 次；试满就标「没看懂」，等面板手填。

外加每日上限（只算成功的）和单线程（一次只看一张），模型限流时不会猛刷。

## 设置在哪

面板「表情包」页 → 「设置」。**设置页右下角固定两个按钮**：「保存」（一次存表情包 + 聊天看图两套）
和「恢复默认」（把每一项填回默认值，再自动保存；默认值就是 2.6 里那串数字）。
另外：

- 设置分两组：左边「基本 / 提示词」，右边「看图 / 容量」，最下面「高级」默认收着；
- 卡片比原来大一圈（190px 起），**点图看大图**（原图本来就小，放大才看得清）；
- **「编辑」弹窗**：左边大图，右边 **名字** + 标签。名字只有一个入口 ——
  想改名就改名字，标签可以手填，也可以点「按名字重算标签」让模型照你这句话补
  （名字是你写的，模型不会改写它）。走 `POST /api/stickers/{sid}/meaning`；
- 只有**缓存区**的卡片有「收下」，点了会先问一句；收下 = 进正式库 + 写一条记忆；
- `×N` 角标 = 这张发出去过几次（只在 N>1 时显示），卡片上不写名字；
- 卡片上黄标「待补」= 收下了但还没看懂；
- 卡片上「缓冲」= 这张在缓冲区等模型恢复；
- 面板分两页：「表情」看图和收图，「设置」放全部旋钮（存完立刻生效）；
- 筛选有「缓存区」和「缓冲区」，按钮上带数字；说明只在切到那一栏时出现一句：
  缓存区（还没收的图，满了淘汰最久没出现的）/ 缓冲区（没看懂，1·5·20 分钟退避重试）；
- 顶部一行「视觉模型今天 x/30 · 聊天看图 y/200 · ×N = 发过几次」就是那个口：
  额度用完会提示「新图先进缓冲区，明天再认」，缓冲区有积压也会说有几张、最多试几次。
  数据来自 `GET /api/stickers` 的 `vision` 字段；
- 设置最下面还有一段「聊天看图」（`look` 块）：**一轮**最多看几张、每天最多看几次、一次等多久；
  额度三项摆在外面，「模型接入」收在一条可折叠横条里（留影 / 直连 / 自定义命令 / 自定义接口，
  见 [视觉接入.md](视觉接入.md)）。
  **计数写在海螺自己的库**（`counters` 表，按天），重启不清零，不碰记忆库。

### 聊天看图别重复花钱

同一张图（按 QQ 图链里的 `fileid` 认，没有就按 URL 的 sha1）当天认过，第二次直接复用那句描述：
不重新调模型、也不占额度。描述存在 `look_cache` 表，**只活当天**——跨天就清。
因为聊天里的图海螺并不下载保存，图链过期图就没了，「图在描述在」在这里不成立；
表情包那边才是跟图走：收下的记录永久留，删图时连记录一起删。

## 存的路径

库里只记相对路径：

- 收下的：`c35c....gif`（在 `data/stickers/`）
- 还没收的：`_cache/c35c....gif`（在 `data/stickers/_cache/`）

整个安装目录搬走也不会裂图（老版本存的绝对路径会在启动时自动收敛成文件名）。
