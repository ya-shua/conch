# 记忆入库（接盘层）

> 2026-11-09 修。改的是 `plugins/conch/main.py` 的 `remember_into_ring` / 新增 `remember_own`。

她「记得什么」有两层：

- **她主动记**：`ring_remember`（她的工具，自己决定记什么、放哪圈）
- **自动入库**：`ring_ingest`（机器工具，不进她的工具清单）—— 桥接层替她记下听到的每一句

这份文档只讲第二层。

## 写进去的四个参数

| 参数 | 值 | 为什么要 |
| --- | --- | --- |
| `conv_key` | 私聊有卡 `private:card:<卡名>`；私聊没卡 `private:<QQ号>`；群 `group:<群号>` | 记忆库按「聊天 + 发言方」分开槽位。**不传就等于所有私聊共用一个槽**：张三和李四会被并成同一条。一卡多号共用卡槽 = 同一个人 |
| `speaker` | `user` / `self` | 只认这两个。卡名不是 speaker，传卡名会被当 `user`；`self` 才有 3 倍存活权重 |
| `message_id` | 入站消息 id；她自己说的是 `out:<turn_id>` | 幂等：同一条重复投递不再写（语音重放、桥接重连都会重发） |
| `note` | 语音等「可能不准」的内容 | 批注，原文不动；`note` 有值时记忆库自己标 `noteSuspect` |

另外 `at` 传真实发生时间（毫秒），记忆库靠它判断「换没换话题」（间隔 > 90 秒或超 5 分钟就新开一条）。

## 她自己的话也要记

`send_lines` 发送成功**之后**才入库（`remember_own`）：

- 没发出去 → 不算她说过，不写
- `speaker="self"` → 记忆库里权重 ×3
- 槽位和对方同一个 `conv_key`：聊的是同一段对话，只是发言方不同（记忆库内部按 `|0` / `|1` 分开）
- 遥控发群（`send_to_group`）也走同一条路

## 实测（隔离库，不碰真库）

```
老爹 private:card:老爹 大号  → 新开一条：大号说话
老爹 private:card:老爹 小号  → 并进上一条：大号说话；小号说话   ← 一卡多号 = 同一个人
外人 private:111 张三        → 新开一条：我是张三
外人 private:222 李四        → 新开一条：我是李四               ← 不是并进上一条
她 self 对老爹              → 新开一条：我在呢                 ← 和 user 分开
重复投递同一 message_id      → 重复投递，没再写
```

## 语音消息（2026-11-09 接上）

1. 收到 `record` 段 → 下载 / 读本地文件
   - QQ 语音实际是 **silk**（文件头前面还带一个 `0x02`），ffmpeg 解不了
   - 所以 silk 走 `plugins/conch/tools/silk_decode.cjs`（node + `vendor/silk-wasm`，纯 wasm）解成 16k PCM，
     自己套 wav 头；其它格式交给 `ffmpeg` 转 mp3
2. POST 到 OpenAI 兼容的 `/audio/transcriptions`（同时最多 `concurrency` 条，默认 2 条并发）
3. 转出来的字当成这条消息的正文，带短标记 `[语音转写] `。
   「语音是机器听的、可能有错」这条规则写在**人设提示**里（每轮一次），不往每条消息后面追提醒。
   纠错方式不额外跑 ASR：让她的对话模型**按上下文顺字**（名字、常用词听错的按对的理解），
   但顺字不许改意思；时间、数字、要做的事拿不准就那句问一句确认
4. 入库时：

```
content : [群123456] 老墨 #120000：[语音转写] 今天下雨，别出门了
note    : 语音转写，可能不准
```

**转写服务从「留影」借**（`留影/data/vision.json` 的 `asr` 段：baseUrl / model / apiKey，
默认硅基流动 `FunAudioLLM/SenseVoiceSmall`），ffmpeg 也用留影自带的 `bin/ffmpeg.exe`。
海螺自己的 `config.json` 可以覆盖：

```json
"asr": {
  "enabled": true,
  "base_url": "", "model": "", "api_key": "", "ffmpeg": "",
  "concurrency": 2   // 同时最多转几条（单模型，2 条足够）
}
```

实测耗时（群里真语音，单条 5.5 秒的语音）：
下载 ~270ms + silk 解码 ~100ms + ASR ~1.0s ≈ **1.0–1.7s 一条**；
3 条同时来 ≈ **2.2s**（串行要 4.5s 以上）。

> QQ 自带的 `fetch_ptt_text` 试过：老消息一律「语音转文字超时（未收到结果推送）」，
> 拿不到字还会拖时间，所以没用它，只留我们自己的 ASR。

留空 = 跟随留影；`enabled: false` = 关掉。
转不出来（没网 / key 失效 / ffmpeg 失败）→ 当没听见，不报错、不拖慢回话。

实测（2026-11-09）：SAPI 合成「今天天气不错，我们下午出去走走吧。」→ 识别原文返回。

## 已知没做的

- 图片 / 表情包不进记忆库（本来也没字）。
- 转写没有并发上限：同时来好几条长语音会排队调用。
