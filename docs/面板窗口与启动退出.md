# 面板窗口 · 一键启动 · 一键退出

三个老毛病（2026-11-09 修完）：

| 症状 | 病因 | 现在 |
|---|---|---|
| 域和海螺一起跑时，点海螺弹出**微光域的浏览器** | 只拿 pid 认窗口，Windows 会回收 pid，微光域那套 Playwright 的 msedge 随时拿到同一个号 | 认进程连**启动时间**一起认；对不上就当过期，重新开 |
| 点海螺**什么都没弹**，日志刷「进程还活着，但窗口还没出来」 | 浏览器被点 X 关掉、进程还在时，旧代码原地等 12 秒然后放弃 —— 那条路永远是死路 | 进程在、窗口没了 → 同一个配置目录里**再开一个窗口**；窗口其实开在别的进程上就按配置目录认回来 |
| 启动慢、完全退出也慢，还关不干净 | ① 启动串行等端口（7 个服务排队等）② 退出时没先请托盘退，托盘看门狗 10 秒后又把全家桶拉回来 | 端口并行等；退出先请托盘自己收（跟菜单「退出」同一条路）；端口释放也并行等 |

## 认窗口的规矩（`scripts/panel_window.py`）

身份 = **pid + 进程启动时间**，写在 `data/panel.proc`（JSON）。
窗口记录同理，写在 `data/panel.hwnd`（`{hwnd, pid, start}`）。

```
点海螺
 ├─ 记着的窗口还在，且属主进程就是当初那个 → 提上来（毫秒级）
 ├─ 记着的浏览器进程还在（启动时间对得上）
 │    ├─ 有窗口 → 提上来
 │    └─ 没窗口（被点 X 了）→ 同配置再开一个窗口（0.3 秒）
 ├─ 记录过期（pid 被回收）
 │    ├─ 面板专用配置的浏览器其实开着 → 按配置目录认回来（~0.7 秒，兜底查一次命令行）
 │    └─ 真的没有 → 新开
 └─ 全程不会「等到超时再报失败」
```

几条别退回去的细节：

- 认窗口**不看标题**：GitHub 页面标题里也有「海螺」，看标题会提错窗口。
- 面板用**独立配置目录** `data/panel-profile`：不跟你平时的浏览器合并，
  也是「按配置目录认窗口」这条兜底的依据（微光域用的是 `微光域/data/profile`）。
- 只在兜底路上才查一次命令行（`Get-CimInstance`，0.4 秒），平时一句都不问。

## 实测（本机，冷启动）

```
起：面板可用 3.2s ｜ 面板窗口 0.6s ｜ 其余端口齐 9.8s
关：所有端口释放 3.5s ｜ 托盘退出 2.5s ｜ 15 秒后确认没有被看门狗拉回来
已经开着再点一次：0.4~0.5s
```

之前是「面板 ~13s、全部端口 ~19s、退出 10~15s 且要关两次」。

## 退出为什么必须先请托盘

`scripts/tray.py` 里有个看门狗：每 5 秒探一次面板，连续两次探不到就
`start_services()` 把全家桶重新拉起来。所以光跑 `stop_all.py` 是关不干净的 ——
关掉的那一秒看着是关了，10 秒后一切照旧。

`stop_all.py` 现在第一件事就是：写 `data/tray.quit` 让托盘走它自己的退出流程
（它停服务、再把自己收掉）。托盘那边拉起来的 `stop_all` 会带
`CONCH_TRAY_QUITTING=1`，跳过「请托盘退出」这一步，避免两边互等。

## 另一处提速

- `start_all.py`：所有服务先全部拉起来，再**一起**等端口（总预算 30 秒，不是每个 30 秒）；
  窗口守卫在不在改成读 `data/guard.lock`（以前要起 powershell 查命令行，冷启动 1~2 秒）。
- `tray.py`：`status()` 先探端口再问 HTTP（面板不在时 urlopen 会被系统代理拖到 2 秒）；
  面板一能应答就开页面，不等所有服务齐。
- `微光域/main.py`：先把 8765 开起来，再在后台线程里定位/隐藏浏览器窗口
  （以前是「起浏览器 → 等窗口 5 秒 → 藏窗口 3.6 秒 → 才开端口」）。
